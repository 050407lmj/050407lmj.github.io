嵌入式系统应用开发

这是一个面向省赛场景的嵌入式系统项目。对我来说，它最重要的不只是写出某个驱动， 而是在有限时间里，把任务分析、模块划分、底层驱动、多任务调度和整机联调真正组织成一个可运行的系统。

Project Notes

  • 项目类型：省赛类嵌入式系统开发
  • 我的角色：任务分析、架构拆分、驱动开发、联调推进
  • 核心栈：CH32H417QEU6、RT-Thread、GPIO、串口、定时器、显示模块
  • 后续可补：整机照片、任务结构图、比赛现场图、演示视频

项目概述

项目面向江苏省职业院校技能大赛嵌入式系统应用开发赛项，要求在规定时间内完成底层驱动搭建、任务调度组织和整机功能联调。 它考验的不是单个知识点，而是工程节奏、架构拆分能力和现场排障能力。

这个项目特别适合做成长页面展示，因为它天然包含多个分支内容：系统方案怎么拆、任务怎么调度、外设怎么联调、稳定性问题怎么定位。

我负责什么

我负责竞赛任务分析、系统架构设计、模块功能划分与开发推进，完成从需求理解、代码实现到整机联调的完整流程。

在联调阶段，我还承担了多外设驱动适配、异常数据定位、任务阻塞排查和通信不稳定优化等工作。

关键模块与分支内容

Branch 01

系统方案设计与任务拆解

先把竞赛任务拆清楚，再决定模块边界和开发顺序，这一步决定了后面联调会不会乱。

  • 分析赛项需求，明确优先级和功能依赖关系。
  • 划分传感器采集、通信交互、外设控制、数据显示等模块。
  • 把“先跑通链路，再逐步优化”作为整体推进策略。

Branch 02

RT-Thread 多任务调度与外设并发

项目不是单模块开发，而是多个外设与任务协同运行，所以我把 RT-Thread 作为系统组织骨架。

  • 基于 RT-Thread 组织多任务并发运行，协调采集、控制、交互和显示。
  • 围绕 GPIO、串口、定时器、通信模块及显示模块进行驱动适配与联调。
  • 优先保证系统链路完整，再逐步调优响应效率与运行稳定性。

Branch 03

整机联调与稳定性问题定位

真正耗时间的是联调阶段。我需要在多个模块同时工作的情况下，快速找到阻塞点和异常源。

  • 处理运行过程中的数据异常、任务阻塞和通信不稳定问题。
  • 通过接口约定和调试顺序控制联调冲突。
  • 把多外设系统真正整合成可持续运行的整机。
